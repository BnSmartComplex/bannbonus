# Database — conceptual PostgreSQL schema
All business tables tenant-scoped where applicable; UUID IDs, created_at/updated_at, version counters, timestamps stored as UTC.
tenants(id,name,status); users(id,tenant_id,role,auth_subject); technicians(id,tenant_id,user_id,is_online,skills,service_zones,last_seen_at); customers(id,tenant_id,contact_encrypted,consent_flags); service_requests(id,tenant_id,customer_id,service_type,area,status,urgency); jobs(id,tenant_id,request_id,status,assigned_technician_id,version); job_visits(id,tenant_id,job_id,technician_id,check_in_at,check_out_at); dispatch_offers(id,tenant_id,job_id,technician_id,status,expires_at); bookings(id,tenant_id,request_id,technician_id,window_start,window_end,status,reviewed_by,reviewed_at); booking_holds(id,tenant_id,technician_id,window_start,window_end,expires_at); job_events(id,tenant_id,job_id,type,actor_id,payload,occurred_at); outbox_events(id,tenant_id,event_type,payload,status,attempts,next_attempt_at); integration_deliveries(id,tenant_id,outbox_id,channel,provider_message_id,status); diagnostic_records(id,tenant_id,job_id,technician_id,measurements,evidence_refs); quotes(id,tenant_id,job_id,version,status,amount,approved_at); documents(id,tenant_id,job_id,type,storage_ref); audit_logs(id,tenant_id,actor_id,action,entity_id,metadata,created_at).
Constraints: unique active visit per technician via partial index; no overlapping confirmed bookings per technician using exclusion constraint on time ranges (including configured buffers) or equivalent serialized booking service; unique idempotency keys scoped to tenant/operation; FK tenant consistency; RLS and application authorization; separate PII from notification payloads.
Before migrations: finalize service duration/buffers, tenancy policy, identity provider, financial rules, retention, booking assignment timing. This file is conceptual, not executable migration.

Add booking_equipment(tenant_id,booking_id,category,brand,model_number,serial_number_nullable,revision_nullable,identification_status), equipment_photos(tenant_id,booking_id,storage_path,kind,uploaded_by,validated_at), device_models(brand,model_number,revision,category,verification_status), device_sources(model_id,source_url,source_type,retrieved_at,applicability,verification_status), device_research_jobs(tenant_id,booking_id,status,idempotency_key,attempts,last_error), diagnostic_evidence(tenant_id,booking_id,source_id,claim,reviewed_by_nullable). Enforce booking fault description and either brand+model or photo with transactional/application validation; maintain tenant isolation, privacy, and source provenance. Schema details subject to migrations/ADR.

## Device dossier and customer identity feedback (conceptual)
Add device_identification_candidates(tenant_id,booking_id,brand,model,revision,evidence,confidence,source), device_identification_responses(tenant_id,booking_id,candidate_id_nullable,response_enum,correction_nullable,responded_at), device_dossiers(tenant_id,booking_id,version,status,model_applicability,generated_at,refreshed_at,snapshot_json), dossier_claims(dossier_id,claim_type,claim_text,source_id_nullable,evidence_level,verification_status), dossier_components(dossier_id,name,function,quantity_nullable,quantity_source_id_nullable,part_number_nullable), dossier_failure_patterns(dossier_id,symptom,model_specific_boolean,evidence_source_id_nullable), dossier_hypotheses(dossier_id,rank,possible_cause,reasoning_evidence,required_checks,safety_class). Persist a usable provisional snapshot as early as possible and version revisions; technician read path must never depend on synchronous web research. Protect PII, source licenses, tenant isolation, and offline-cache revocation.
